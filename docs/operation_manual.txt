================================================================================
三、舵机校准（Calibration）
================================================================================

1. 校准从臂：

    lerobot-calibrate --robot.type=so101_follower --robot.port=COM24 --robot.id=my_awesome_follower_arm

2. 校准主臂：

    lerobot-calibrate --teleop.type=so101_leader --teleop.port=COM22 --teleop.id=my_awesome_leader_arm

3. 交互流程：
   (1) 若已有校准文件，提示按 ENTER 沿用 / 输入 c 重新校准；
   (2) 摆中位：把每个关节手动摆到"活动行程的正中间"，按 ENTER；
   (3) 缓慢转动每个关节到两个极限位置（双向转到头），完成后按 ENTER。

4. 校准合格判据：
   - 每个关节 MIN < 2047 < MAX（中位必须落在区间内）；
   - 所有值在 0 ~ 4095 之间，不允许出现 0、32xxx 等异常值；
   - MAX - MIN 宽度小于 4095，不跨编码器翻转点。

5. 踩坑记录：
   - 【溢出坑】通电期间舵机跨过编码器零点会累计负值（显示为 32768+|v|）。
     解决：摆到中位附近后【断电重启】再校准。
   - 【单向坑】wrist_roll 只朝一个方向转会记出跨翻转点的错误区间，必须双向转到头。
   - 校准文件位置：
       C:\Users\lithos\.cache\huggingface\lerobot\calibration\robots\so101_follower\my_awesome_follower_arm.json
       C:\Users\lithos\.cache\huggingface\lerobot\calibration\teleoperators\so101_leader\my_awesome_leader_arm.json

6. 单关节重新校准（只重标某一个关节）：

    python examples\recalibrate_single_joint.py --arm leader --port COM22 --id my_awesome_leader_arm --motor wrist_roll

--------------------------------------------------------------------------------
5.1 物理准备（只做一次）
--------------------------------------------------------------------------------

  - 打印 dental_robot\markers\ 里两张 ArUco 码，黑方块边长必须精确 30mm
    （量一下，不符就改 config.py 的 MARKER_SIZE_M）；
  - ID 0 贴牙模上/旁边，ID 1 贴机械臂基座旁的桌面上（不是贴机械臂上！）；
  - 基准码（ID 1）朝向：让牙模工作区落在 0° 附近（±180° 缝留在正后方）；
  - 场景相机 (index 0) 选好机位后彻底锁死，之后到部署都不能再动；
  - 光照必须固定，采集与部署用同一光源。

--------------------------------------------------------------------------------
5.2 标定链路（按顺序执行，每步只做一次）
--------------------------------------------------------------------------------

步骤 1：场景相机内参标定（需要 9x6 棋盘格，方格边长 28.5mm）

    python -m dental_robot.calibrate_scene_camera

  操作：把棋盘格对着相机，不同角度/距离展示。
  按键：SPACE = 拍照（需要 >= 15 张），c = 标定并保存，q = 退出。
  合格判据：RMS 重投影误差 < 0.5 px。
  产出文件：dental_robot/scene_camera_intrinsics.npz

步骤 2：方位角→舵机映射标定

    python -m dental_robot.calibrate_pan_mapping

  操作：
    (1) 把牙模放到工作区某个位置；
    (2) 用 a/d 粗调、A/D 细调让基座对准牙模；
    (3) 按 SPACE 记录一组 (azimuth, shoulder_pan) 样本对；
    (4) 重复 4~6 个不同位置；
    (5) 按 f 拟合保存，q 退出。
  产出文件：dental_robot/pan_mapping.json

步骤 3：对准验收

    python -m dental_robot.align_base

  随便挪牙模，基座应稳定转到对准位。重复 5 次误差稳定即通过。

步骤 4：标定臂关节起始姿态（只跑一次）

    python -m dental_robot.calibrate_start_pose

  操作：
    (1) 脚本启动后，通过主臂遥操把从臂摆到理想的录制起始姿态；
    (2) 屏幕显示 ID 2-6 的实时位置；
    (3) 按【空格】保存，按【ESC】取消。
  产出文件：dental_robot/start_pose.json
  原理：ArUco 对齐处理 ID 1（shoulder_pan），此标定处理 ID 2-6。
        两者结合，每个 episode 的 6 个关节起始位都是确定的。

步骤 5（可选）：场景几何标定

    python -m dental_robot.calibrate_scene_geometry

  锁定相机/基座/牙模的空间关系，align_base 会直接用保存的 canonical
  shoulder_pan 而非映射计算值，精度更高。

5.3 数据采集
--------------------------------------------------------------------------------

首次采集（新建数据集，默认存到 ./data/dental，无需指定 --dataset_root）：

    python -m dental_robot.record_episodes --dataset_repo_id local/dental_drilling --num_episodes 5 --episode_time 300 --task "Simulate holding a dental handpiece and drilling" --display_data

追加采集（已有数据集，加 --resume）：

    python -m dental_robot.record_episodes --dataset_repo_id local/dental_drilling --num_episodes 1 --episode_time 300 --task "Simulate holding a dental handpiece and drilling" --display_data --resume

注意：
  - --num_episodes 是本次要录的数量，不是总数；
  - --resume 表示追加，不覆盖已有数据；
  - data/dental 目录已存在但不加 --resume 会报 FileExistsError；
  - 不要再使用旧路径 ./data_dental（已迁移到 data/dental），
    指定不存在的路径会回退去连 HuggingFace Hub 并报超时/401；
  - --episode_time 300 是上限，动作完成后按空格键提前结束；
  - --display_data 开启 Rerun 双相机实时预览；
  - 首次试录建议 --num_episodes 2，确认稳定再正式开采。

每回合流程（全自动，无需手动摆 leader）：
  (1) 摆牙模到新位置 → 在弹出的摄像头窗口中确认牙模在画面内 → 按 ENTER；
  (2) 自动回收复位（防碰撞顺序）：先预抬腕 ID 4（把钻头抬离牙模）→
      ArUco 对齐基座 (ID 1) → 自动归位臂关节 (ID 2-6)；
  (3) 双摄像头预览窗口弹出 → 按 ENTER 开始录制；
  (4) 通过主臂遥操完成任务 → 按【空格键】结束并保存。

键盘控制：
  空格键     = 结束当前回合（保存）
  右方向键   = 提前结束回合（同空格）
  左方向键   = 废弃当前回合，重新录制
  Esc        = 结束整个采集会话

数据量参考：30~50 回合约 2~5 GB。

5.4 轨迹平滑（训练前必做！）
--------------------------------------------------------------------------------

遥操作采集的原始数据含舵机抖动，直接训练会让部署时舵机频繁抖动。
训练前必须跑一遍 Savitzky-Golay 平滑：

    python -m dental_robot.smooth_trajectories --backup --export_csv

追加采集后的增量平滑（只处理新录回合，避免用已平滑数据覆盖原始备份）：

    python -m dental_robot.smooth_trajectories --episodes 33 34 35 ... 49 --backup --export_csv

参数：
  --episodes N N ...  只处理指定回合（默认全部）
  --window 15         滤波窗口帧数（奇数，默认 15 ≈ 0.5s@30fps）
  --polyorder 2       多项式阶数
  --backup            平滑前备份原始 parquet 到 data/backups/dental_pre_smooth/
  --export_csv        同步重导出 joint_trajectories/ 下的 CSV
  --dry_run           只打印抖动降幅，不写盘

说明：
  - 处理 action 和 observation.state 两列；平滑后同步更新
    meta/episodes_stats.jsonl 中对应特征的统计量；
  - 备份目录必须位于数据集目录之外（save_episode 用 rglob 递归校验
    parquet 数量，混入备份会导致断言失败）；
  - 抽查平滑效果（生成对比图）：
      python -m dental_robot.plot_smoothing_comparison --episode 5
      输出到 outputs/smoothing_comparison_episode_5.png

训练前置检查（已内置到 train_act.py，无需人工自查）：
  训练启动前自动逐回合检测 action 轨迹粗糙度（二阶差分均值，阈值 0.05），
  发现未平滑回合会立即中止训练并打印修复命令；加 --auto_smooth 可当场
  自动平滑。详见 5.5。

--------------------------------------------------------------------------------
5.5 训练 ACT 策略
--------------------------------------------------------------------------------

使用本地 GPU 训练（推荐：CUDA + 混合精度，50000 步约 3.5~4 小时）：

    python -m dental_robot.train_act --dataset_repo_id local/dental_drilling --use_amp

说明：
  - 设备自动检测：有可用 CUDA 时自动用 GPU，无需额外指定 --device；
  - --use_amp 开启 FP16 混合精度：更省显存、速度更快，有 GPU 就开；
  - 训练前先确认 GPU 可用（必须输出 True，否则参考排查章节重装 CUDA 版 PyTorch）：
      python -c "import torch; print(torch.cuda.is_available())"
  - 预期进度：约 0.27 秒/步，loss 从 ~15 降到 2 左右属正常收敛；
  - 中断后续训：先确认 checkpoints/last/ 已存在（训练满 5000 步才会存档），
    再加 --resume；否则从头跑（不要对不存在的 last/ 续训）。

常用参数：
  --steps 50000       训练步数（默认 5 万步）
  --batch_size 8      批大小（显存不够改 4）
  --val_episodes 2    留最后 N 个回合做验证集
  --lr 1e-5           学习率（ACT 默认值）
  --chunk_size 100    动作块大小（预测未来 100 步）
  --resume            断点续训
  --no_pretrained     跳过 ResNet18 预训练权重下载（网络不好时用）
  --device cuda       强制使用 GPU（默认自动检测）
  --use_amp           CUDA 混合精度（更省显存、更快，有 GPU 就开）
  --wandb             开启 WandB 训练记录
  --auto_smooth       平滑前置检查不通过时自动就地平滑数据集
  --skip_smoothing_check  跳过平滑前置检查（仅限明确知道数据已平滑）
  --smoothing_threshold 0.05  平滑检查的粗糙度阈值

训练进度：每 100 步打印 loss/梯度/学习率，每 1000 步跑验证集，
          每 5000 步存一个 checkpoint。

检查点输出目录：outputs/train/act_dental/checkpoints/
  best/     验证 loss 最优（部署用这个）
  last/     最新（断点续训用）
  NNNNNN/   按步数存档

数据量建议：5 组可跑 demo 验证流程，正式训练建议 20~50 组。

--------------------------------------------------------------------------------
5.6 端到端部署
--------------------------------------------------------------------------------

什么是端到端（end-to-end）部署：
  “端”指“输入端”和“输出端”。训练好的 ACT 策略直接把
  相机图像 + 关节状态（输入端）映射成 6 关节控制指令（输出端），
  中间不需要人工编写运动规则、轨迹规划或分步编排。
  对比传统机器人“感知→规划→控制”的分段式流水线（每段手工开发、
  误差逐级累积），端到端是数据驱动的：人手把手示教多少，机器人就
  学会多少，训练完直接上真机。代价是部署条件必须和采集条件一致
  （同一相机机位、光照、起始姿态），所以本项目用 ArUco 对齐把
  场景归一化，把“分布漂移”压到最小。

部署命令：

    python -m dental_robot.run_pipeline --policy_path outputs/train/act_dental/checkpoints/best/pretrained_model

参数：
  --duration 20       策略运行秒数（默认 20s）
  --skip_align        跳过 ArUco 对准，只跑阶段2（调试用）

完整流程（一条命令后全自动，无需人工干预）：
  (1) 阶段1（几何归一化）：场景相机检测 ArUco 码 → 转动底座 ID 1
      对准牙模 → 臂关节 ID 2-6 归位到标定起始姿态；
  (2) 阶段2（端到端推理）：以 30fps 循环读取双相机图像 + 6 关节状态
      → ACT 策略预测未来 100 步动作块 → 下发舵机执行；
  (3) 到达 duration 后策略退出，机械臂自动回收到起始姿态（预抬腕
      ID 4 → 归位 ID 2-6）。
按 Ctrl+C 可随时中断。

--------------------------------------------------------------------------------
5.7 上游适配补丁（patches/）
--------------------------------------------------------------------------------

本仓库基于上游 huggingface/lerobot，适配修改全部收敛在 patches/ 目录
（5 个 .patch + README.md + apply_patches.ps1），方便上游升级时重放：

  0001-opencv-flip-horizontal   OpenCV 相机水平翻转支持（功能性，必须保留）
  0002-motors-bus-retry         舵机总线读写重试机制（功能性，必须保留）
  0003-so101-wraparound-guard   SO-101 关节环绕保护（功能性，必须保留）
  0004-configs-windows-tempfile Windows 临时目录兼容（功能性，必须保留）
  0005-ruff-sim-lint            纯 lint 修复（上游更新后可按需重做）

上游同步流程：
  (1) git checkout -b upstream-sync <新的上游提交>
  (2) .\patches\apply_patches.ps1            # 批量重放全部补丁
      .\patches\apply_patches.ps1 -CheckOnly  # 只预检不落盘
  (3) 冲突时用 git apply --3way 三方合并，手工解完后继续下一个补丁
  (4) 验证通过后合并回 main

补丁基线为 origin/mypy_support（8b4dcb14）；适配文件变动后需重新生成：
  git diff --output=patches\000X-xxx.patch 8b4dcb14 HEAD -- <涉及文件>
  （注意：必须用 --output 参数，PowerShell 的 > 重定向会写 UTF-16 导致补丁失效）

================================================================================
六、常见问题排查
================================================================================

【Overload error（舵机过载）】
  现象：RuntimeError: Failed to write ... Overload error!
  原因：CH343 串口通信不稳定，或舵机物理堵转/供电不足。
  解决：
    (1) 代码已内置重试机制（config.py 的 _write_calibration_with_retry）；
    (2) disconnect 时的 Overload 是非致命的，代码已捕获并打印警告；
    (3) 如果反复出现，断电重启机械臂（拔电源等 5 秒再插上）；
    (4) 检查舵机是否被卡住（物理堵转），检查电源是否稳定（5V/10A）。

【ArUco 检测失败（0/N 帧）】
  现象：RuntimeError: Markers detected in only 0/10 frames
  原因：摄像头索引错误、marker 不在画面内、光照不足、图像被翻转。
  解决：
    (1) 脚本会自动弹出调试预览窗口，检查画面中能否看到 marker；
    (2) 确认 config.py 中 SCENE_CAM_INDEX 对应的是环境相机（不是爪子相机）；
    (3) 环境相机 (fixed) 严禁 flip_horizontal=True，否则 ArUco 角点手性被破坏；
    (4) 改善光照，避免强反光。

【摄像头索引变了】
  现象：画面显示的是爪子相机而不是环境相机（或反过来）。
  解决：
    (1) 跑 lerobot-find-cameras opencv，看 opencv_0.png 和 opencv_1.png；
    (2) 改 config.py 中 SCENE_CAM_INDEX 和 HANDEYE_CAM_INDEX 的值。

【PyTorch CUDA 不可用（训练用 CPU 很慢）】
  现象：WARNING: Using CPU, this will be slow.
  原因：conda 环境装的是 CPU 版 PyTorch。
  解决（在 lerobot 环境中执行）：
    pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu118
  注意：不要加 -i 镜像源参数，否则会覆盖 --index-url 导致装回 CPU 版。
  验证：python -c "import torch; print(torch.cuda.is_available())"  应输出 True。

【ResNet18 预训练权重下载失败】
  现象：ConnectionResetError / URLError 下载 resnet18-f37072fd.pth 失败。
  解决（二选一）：
    (1) 训练时加 --no_pretrained 跳过预训练权重（用随机初始化）；
    (2) 手动下载 https://download.pytorch.org/models/resnet18-f37072fd.pth
        放到 C:\Users\lithos\.cache\torch\hub\checkpoints\resnet18-f37072fd.pth

【FileExistsError: data_dental 目录已存在】
  解决（二选一）：
    (1) 删除后重建：rmdir /s /q data_dental
    (2) 追加模式：加 --resume 参数

【舵机 ID 3 不动（其他正常）】
  现象：遥操时 elbow_flex 没反应。
  排查：
    (1) 跑 python examples\_bus_diag.py，看 sync_read 能否读到 m3；
    (2) 如果读得到但不动 → 扭矩可能被关了，断电重启即可；
    (3) 如果读不到 → ID 2→3 之间的菊花链线缆松了，断电重新插拔。

【录制 --resume 时报 HF Hub 连接超时 / 401 Unauthorized】
  现象：FileNotFoundError: data\dental\meta\info.json 之后回退下载 Hub 并超时。
  原因：本地 meta 与实际数据不一致（如上次录制崩溃丢了一条 episode），
        或 --dataset_root 指向了不存在的旧路径。
  解决：
    (1) 检查 meta/info.json 的 total_episodes 与 data/chunk-000/ 下
        parquet 文件数量是否一致；不一致时手工回退 meta
        （episodes.jsonl、episodes_stats.jsonl 同步删除末尾条目）；
    (2) 数据集根目录已统一为 ./data/dental（脚本默认值），
        不要再用旧路径 ./data_dental。

【save_episode 断言失败：parquet 数量 != num_episodes】
  原因：数据集目录内混入了备份 parquet（save_episode 用 rglob 递归统计）。
  解决：所有备份必须放在数据集目录之外（当前统一放 data/backups/ 下）。

【ModuleNotFoundError: scipy / matplotlib】
  原因：lerobot conda 环境默认不含这两个库（平滑脚本/对比图需要）。
  解决：pip install scipy matplotlib（网络不稳时多重试几次）。

【disconnect 报错（非致命）】
  现象：程序退出时报 RuntimeError: Failed to write 'Torque_Enable'...
  说明：这是 CH343 串口关闭时的已知问题，代码已捕获。
        串口关闭后舵机自然断电，不影响安全。

================================================================================
八、关键铁律
================================================================================

  - 每条训练数据都必须从 align_base 对准后的归一化姿态开始录制
    （record_episodes.py 已固化该协议，不要用 --skip_align 采正式数据）；
  - start_pose.json 必须在 ArUco 校准完成后立即标定（只跑一次），
    此后每个 episode 的 6 个关节起始位全部确定，不再需要手动摆 leader；
  - 场景相机 fixed(index 0) 严禁 flip：镜像会破坏 ArUco 角点手性，
    悄悄毁掉 PnP 位姿解算；爪子相机 handeye(index 1) 保持 flip_horizontal=True；
  - 挪了基准码/基座 → 重标 pan 映射（约 10 分钟）；
    挪了场景相机 → 已录的 ACT 数据全部作废（最贵，千万别碰）；
  - 训练和部署必须使用同一套 config.py 参数（相机索引、marker 尺寸等）；
  - 训练前必须完成轨迹平滑（见 5.4）；train_act.py 已内置平滑前置检查，
    未平滑数据会被自动拦截（--auto_smooth 可自动修复）；
    追加采集后只平滑新增回合即可（--episodes）；
  - 机械臂回收顺序固定：预抬腕 ID 4 → 转底座 ID 1 → 归位 ID 2-6，
    严禁在钻头低位时旋转底座（会扫过牙模）；
  - 数据集统一用 ./data/dental；所有备份放 data/backups/，
    数据集目录内部严禁出现备份文件。
